## Установка

Запускайте из папки проекта. Нужны Git, curl, CLI клиента и uv или Python 3.11+.

**Обычная**

```sh
curl -fsSL https://raw.githubusercontent.com/pnetcloud/plex-ai/main/install.sh | bash
```

**Dev-режим · Codex**

```sh
curl -fsSL https://raw.githubusercontent.com/pnetcloud/plex-ai/main/install.sh | bash -s -- --dev --client codex
```

Выберите клиента, область, команду и профиль, затем подтвердите план. Рекомендуется область **Project**. После установки откройте новую сессию клиента.

Профиль настраивает субагентов. Модель root coordinator выбирайте в основном чате;
план показывает рекомендацию. Подробнее: [основной чат и команда](../../../docs/translations/ru/product.md#основной-чат-и-команда).

## Основные команды

Если команды `plex` нет — например, после первой dev-установки — используйте `~/.local/share/plex-ai/setup.sh` вместо `plex` в командах ниже.

| Задача | Команда |
|---|---|
| Настроить или обновить конфигурацию проекта | `plex` |
| Проверить конфигурацию | `plex status` |
| Загрузить новый релиз и открыть установщик | `plex update` |
| Посмотреть план установки без записи | `plex --dry-run --client codex --project .` |
| Посмотреть план удаления | `plex uninstall --dry-run` |
| Удалить команду проекта | `plex uninstall` |
| Получить статус в JSON | `plex status --json` |
| Получить план удаления в JSON | `plex uninstall --dry-run --json` |

Если команда уже установлена:

| Параметр | Назначение |
|---|---|
| **Update only** | Сохранить настройки и обновить управляемые файлы. |
| **Reconfigure** | Открыть меню с сохранёнными значениями. |

Явные параметры CLI продолжают действовать. `plex` использует текущую рабочую копию; `plex update` загружает новый опубликованный релиз, включая preview.

## Dev-режим

- Только Codex и область **project**. Обе папки скиллов Plex подключаются ссылками на исходники; сохраняйте эту рабочую копию.
- В проекте отключается общий плагин, а управляемый блок инструкций выбирает локальные скиллы Plex. Codex должен доверять проекту. Облачные плагины и другие одноимённые скиллы не отключаются.
- Изменения скиллов доступны через ссылки. После изменения ролей, профилей и каталога workflow обновите установку и откройте новую сессию. Режим сохраняется до `--no-dev`.

| Задача | Команда |
|---|---|
| Подключить рабочую копию | `./setup.sh --dev --client codex --project /path/to/project` |
| Вернуться к общему плагину | `./setup.sh --no-dev --client codex --project /path/to/project` |

## BMad

Нужны Node.js/npm и uv. Выберите команду `bmad` в меню или выполните:

| Задача | Команда |
|---|---|
| Установить выбранные официальные скиллы и runtime проекта | `plex --team bmad --client codex --install-bmad` |
| Инициализировать проект из уже установленных скиллов | `plex --team bmad --client codex --init-bmad` |

Скиллы общие для пользователя; выбранные skill-файлы могут заменяться. Runtime принадлежит проекту. Установленные зависимости/runtime остаются после отмены или последующей ошибки. Для запуска без вопросов добавьте `--project . --yes`: принимаются показанные значения BMad по умолчанию.

## Справочник параметров

Пропущенные настройки сохраняют свои значения. `interaction` явно записывается в каждый применённый preset. Профили, переопределения и пути описаны в [конфигурации](../../../docs/translations/ru/configuration.md).

### Клиенты и область

| Параметр | Назначение |
|---|---|
| `--project PATH` | Существующая папка проекта. |
| `--client CLIENT` | codex, claude или antigravity; можно повторить для нескольких клиентов. |
| `--host CLIENT` | Совместимый псевдоним одного клиента; допускает профили вендоров. |
| `--scope project / user` | Область ролей/инструкций; по умолчанию project. Обычные плагины общие для пользователя. |
| `--instructions / --no-instructions` | Управлять блоком Plex в инструкциях или пропустить его. |

### Команда и модели

| Параметр | Назначение |
|---|---|
| `--team pnet / bmad` | Набор ролей; для новой установки — pnet. |
| `--model-profile PROFILE` | inherit, basic, plus, pro или pro-plus. |
| `--interaction MODE` | interactive, balanced (по умолчанию) или auto. |
| `--max-agents N` | Положительный лимит параллельных поручений. |

### Выполнение и вывод

| Параметр | Назначение |
|---|---|
| `--dev / --no-dev` | Подключить локальные скиллы или выйти из dev; только Codex/project. |
| `--roles-only` | Не устанавливать плагин Plex; явные флаги BMad действуют. |
| `--command / --no-command` | Создать ~/.local/bin/plex (по умолчанию) или пропустить; dev не создаёт команду. |
| `--install-command` | Установить только команду; чужую не заменяет, несовместим с --dev. |
| `--dry-run` | Предпросмотр без записи; несовместим с --install-command. |
| `--yes` | Применить без вопросов; нужны клиент и путь проекта (путь необязателен при --scope user). |
| `--json` | JSON для status или uninstall, включая план удаления. |
| `-h / --help` | Показать сгруппированную справку и примеры. |

### BMad

| Параметр | Назначение |
|---|---|
| `--install-bmad` | Разрешить установку выбранных пользовательских скиллов и недостающего runtime. |
| `--init-bmad` | Инициализировать runtime установленным официальным setup. |
| `--bmad-skill PATH` | Явный путь к установленному setup-скиллу BMad. |

### Источник — update / GitHub-установщик

| Параметр | Назначение |
|---|---|
| `--release TAG` | Использовать тег релиза, например v0.5.4. |
| `--development` | Использовать main; не включает --dev. |
| `--checkout PATH` | Только GitHub-установщик; по умолчанию ~/.local/share/plex-ai. |

GitHub-установщик хранит общую рабочую копию в `~/.local/share/plex-ai`; не удаляйте её. `--dry-run` загрузчика/update проверяет только выбор исходников; остальные параметры передаются в setup.

## Сохранность файлов и решение проблем

- Удаление по умолчанию работает на уровне проекта. `--client codex` ограничивает клиента, `--scope user` выбирает пользовательские роли, `--yes` подтверждает удаление без вопросов.
- Удаляются только неизменённые управляемые роли, блоки инструкций и dev-ссылки/override. Общие плагины, исходники, настройки и backups остаются; изменённые управляемые файлы и неизвестные форматы останавливают операцию.
- Обновление исходников отказывается менять грязную, чужую или подключённую симлинком копию. Изменения менеджера плагинов и завершённые установки клиентов отделены от отката файлов ролей.
- `status` сначала проверяет проект, иначе — пользовательскую область. Он проверяет конфигурацию и обнаружение плагина, а не фактический выбор моделей.

| Если… | Что использовать |
|---|---|
| plex отсутствует в PATH | ~/.local/bin/plex или ./setup.sh из рабочей копии. |
| Команда принадлежит другой копии | Напечатанный путь к setup.sh; чужая команда сохраняется. |
| Конфликт скилла или управляемого файла | Проверьте указанный файл: установщик его не перезаписывает. |
| Существующий override плагина блокирует --dev | Вручную задайте enabled = false; существующий override сохраняется после выхода. |

## Вывод

Цвет включается только в терминале. `NO_COLOR=1` или `TERM=dumb` включает простой вывод и меню с номерами; перенаправленный вывод обычный. С `--json` в stdout нет оформления и сообщений о ходе работы.
