# Установка и параметры командной строки

[English](../../installation.md) · [Русский](../ru/installation.md) · [Deutsch](../de/installation.md) · [简体中文](../zh-CN/installation.md)

Нужны Git, curl, CLI выбранного клиента и uv или Python 3.11+. Для установки зависимостей BMad также нужны Node.js/npm и uv.

## Установка и обновление

Для первой установки используйте [быстрый старт](../../../README.ru.md#быстрый-старт).
Скрипт хранит общую копию в `~/.local/share/plex-ai` и устанавливает последний
**опубликованный релиз, включая preview**. Сохраняйте эту копию: плагины ссылаются на неё.
Сам входной скрипт берётся из `main`, а файлы приложения — из выбранного тега релиза.

```sh
curl -fsSL https://raw.githubusercontent.com/pnetcloud/plex-ai/main/install.sh | bash
```

### Состояние, обновление и удаление

```sh
plex status
plex status --json
plex update
plex update --release v0.2.0
plex update --development
plex uninstall --dry-run
plex uninstall
```

`status` сначала проверяет конфигурацию проекта, иначе пользовательскую установку
соответствующего клиента. Показывает версию исходников, команду/профиль, роли,
конфликты и обнаружение плагина, не меняя конфигурацию Plex. `--json` даёт структурированный
вывод. Для настроенных клиентов с конфликтом, устаревшим состоянием или недоступным
плагином код выхода ненулевой. Фактическую маршрутизацию моделей это не подтверждает.

`update` выбирает последний опубликованный релиз и открывает настройку для обновления
выбранных клиентов. `--release` закрепляет опубликованный тег; `--development` явно
выбирает `main`. Локальные изменения, символические ссылки и чужой origin блокируют
обновление. Исходники переключаются на конкретный тег, а не плавающую ветку.
`update --dry-run` показывает выбор версии без записи исходников и конфигурации.

`uninstall` по умолчанию работает в проекте со всеми клиентами из receipt.
`--dry-run` показывает план; интерактивное удаление запрашивает подтверждение,
для запуска без вопросов нужен `--yes`. Клиента можно выбрать через `--client codex`,
пользовательскую область — явно через `--scope user`. Удаляются только неизменённые
роли из receipt и совпадающий управляемый блок. Изменённые/отсутствующие файлы и
неправильные маркеры останавливают операцию. Чужие файлы и окружающий текст остаются.
Общий блок сохраняется, пока нужен другому клиенту. У каждого клиента собственные
lock, транзакция и резервные копии; удаление нескольких клиентов не является общей транзакцией.

Общие плагины, исходники, команда CLI, редактируемый preset и backups сохраняются для
других проектов или переустановки. Нативный файл инструкций после удаления блока остаётся.
Сохранённые проектные настройки продолжают иметь приоритет над глобальными; область
автоматически не переключается. После изменений откройте новую сессию клиента.
Если `plex` нет в PATH, используйте `~/.local/bin/plex`. Обычный `plex` открывает настройку.

Из checkout запустите `./setup.sh`. Пробел отмечает клиентов, Enter продолжает.
Выберите команду, область установки и общий профиль; проверьте план каждого клиента.
По умолчанию выбрана область проекта. Нужен установленный CLI соответствующего клиента.

```sh
./setup.sh --project /path/to/project --client codex --client antigravity --team pnet --model-profile plus --yes
```

Полная установка добавляет общий плагин Plex и настраивает нативные роли/инструкции.
Скилы не дублируются в проектах. Пока локальный marketplace ссылается на исходники
или экспорт, сохраняйте их. Для BMad нужны установленный runtime проекта и подходящие скилы.

Повторный setup обновляет определения или переключает команду/профиль, сохраняя
переопределения. Изменения попадут в установленные роли после обновления; для загрузки
новых скилов/ролей начните свежую сессию клиента. Общий профиль проекта обновляет
уже настроенных клиентов; клиент без receipt не устанавливается автоматически.


Изменения менеджера плагинов и завершённые установки клиентов не откатываются при сбое следующего клиента.

Существующая команда из другой копии, чужой файл или битая ссылка сохраняются
с уведомлением и не блокируют обычную установку. Установщик показывает свой путь
запуска. Явный `--install-command` по-прежнему не перезаписывает чужую команду.

Если у команды `bmad` в проекте нет runtime, установщик предлагает официальную
инициализацию, переход на `pnet` или отмену. Если нет setup-скилла BMad, отдельно
предлагается установка зависимостей для пользователя. Требуется явное согласие:
выбранные пользовательские skills могут быть заменены и используются другими
проектами. Существующие плагины остаются нетронутыми.

`--install-bmad` разрешает эту установку и инициализацию проекта; `--init-bmad`
использует уже установленные skills. `--yes` принимает показанные значения модулей
по умолчанию. `--dry-run` ничего не записывает. После подтверждения плана используется
официальный setup BMad и задаются только неотвеченные вопросы модулей. Runtime и
зависимости сохраняются, если следующий шаг завершится ошибкой.

Новая установка использует `skills@1.7.4` и официальную ревизию BMad
`495ef6e0996d07b23359cc4d6c73a1aa2f3ba5ad`: только входные и workflow-skills команды,
скилл `bmad` и две записи модулей. В набор входит PO, которого пока нет в plugin
marketplace. Нужны Node.js/npm и `uv`. Официальный Skills CLI поддерживает Codex,
Claude Code и Antigravity.

При обнаружении приоритетны прямые skills проекта/пользователя. Также поддерживаются
включённые установленные Toolbox-плагины Codex/Claude; наличие cache недостаточно.
Явный путь к hub задаётся через `--bmad-skill /path/to/installed/bmad`. При
пользовательских ролях runtime всё равно нужен в каждом рабочем проекте.


## Существующая установка и совместимость

После выбора клиента, области и проекта установщик определяет существующую команду
по записи установки и предлагает **Update only** (`refresh`, только обновить) или
**Reconfigure** (`configure`, перенастроить). По умолчанию выбрано обновление;
явные параметры настройки делают перенастройку вариантом по умолчанию. Обновление
пропускает вопросы о команде, профиле, режиме и параллельности, сохраняя выбор блока
инструкций отдельно для каждого клиента. Явные параметры CLI продолжают действовать;
план всегда нужно подтвердить. Для нескольких клиентов действие переиспользуется
после обнаружения первой установленной команды. Один общий плагин ещё не означает,
что команда установлена в новом проекте.

При `--yes` текущие настройки сохраняются, если не переданы явные изменения.
Перенастройка открывает обычные меню с сохранёнными значениями. Отсутствующие
зависимости BMad всё ещё могут потребовать решения; обновление не предлагает
переключиться на другую команду. Обновляются определения из текущей рабочей копии;
для загрузки новых исходников используйте `plex update` или GitHub-установщик.
Dev-режим сохраняется и продолжает использовать локальный источник.

Совместимость остаётся в существующем resolver: добавляются недостающие значения,
сохраняются переопределения, обновляются поддерживаемые старые маркеры. Старые
идентификаторы профилей вендоров при обновлении сохраняются. Замена управляемых файлов
использует существующие резервные копии и проверки владения. Изменённые управляемые
файлы и неизвестные поля конфигурации или записи установки останавливают операцию;
личный текст и чужие файлы сохраняются. Принудительного сброса и универсальной системы
миграций нет. Изменения менеджера плагинов отделены от отката файлов ролей.

## Локальная разработка с Codex

Из рабочей копии Plex подключите тестовый проект без выпуска релиза:

```sh
./setup.sh --dev --client codex --project /path/to/test-project
```

Доступно с v0.5.0; запускайте из той рабочей копии, скиллы которой хотите тестировать.

`--dev` поддерживает Codex на уровне проекта. Полные папки скиллов `plex` и
`plex-setup` подключаются ссылками в `.agents/skills/`, а `pnet-plex@pnet-plex`
отключается в проектном `.codex/config.toml`. Пользовательская конфигурация и
другие проекты не меняются. Codex должен доверять проекту, чтобы читать его конфигурацию.
Облачные плагины и другие одноимённые скиллы этим не отключаются.

Управляемый блок `AGENTS.md` (или выбранного файла инструкций) требует брать эти
два скилла Plex только из проекта. Сначала нужно раскрыть ссылки: references,
проверяющий скрипт, `teams/`, координатор и профили берутся из той же рабочей копии.
BMad остаётся отдельной установленной зависимостью. Не удаляйте рабочую копию.

Правки скиллов сразу доступны через ссылки; откройте новую сессию Codex для их загрузки.
После изменения агентов, профилей или каталога workflow повторите установку.
`plex status --client codex` показывает настроенный dev-источник и проверяет ссылки
и локальное отключение плагина, но не доказывает загрузку инструкций работающей моделью.
Повторная установка сохраняет dev-режим, если не передать `--no-dev`.

```sh
./setup.sh --no-dev --client codex --project /path/to/test-project
```

`--no-dev` убирает принадлежащие Plex ссылки и отключение плагина, обновляет команду
и возвращает установку общего плагина. `plex uninstall` тоже очищает dev-настройки.
Чужие скиллы и изменённые ссылки/настройки блокируют изменение. Существующий явный
override плагина сохраняется: включённый нужно вручную переключить на `false`
перед `--dev`; ранее установленный `false` останется и после выхода.
Личный текст инструкций сохраняется. `.plex/dev.json` хранит локальный источник
и владение override; не коммитьте это машинное состояние. `--dry-run` ничего не пишет.
`--dev` независим от `plex update --development`, который выбирает `main`.

## Вывод в терминале

Установка, status, обновление исходников и удаление используют одинаковые заголовки,
выровненные параметры, таблицы агентов/моделей и выделенные команды. Зелёный обозначает
успех, жёлтый — предупреждения, красный — ошибки; пути и пояснения приглушены.
План показывает файл управляемых инструкций без полного текста шаблона.
В узком терминале настройки агентов располагаются друг под другом вместо таблицы.

Цвет и выделение включаются только в терминале. При перенаправлении вывод остаётся
обычным; `NO_COLOR=1` или `TERM=dumb` также включают простой вывод и меню с номерами.
В `--help` параметры сгруппированы по назначению. Для машинного чтения status и
удаления используйте `--json`, в том числе при предпросмотре удаления:
stdout содержит только JSON, без оформления и сообщений о ходе работы.

```sh
plex --help
plex status
plex status --json
plex uninstall --dry-run
plex uninstall --dry-run --json
NO_COLOR=1 plex status
```

## Команды

| Команда | Действие |
|---|---|
| `plex setup` | Открыть установку; это также действие по умолчанию. |
| `plex status` | Проверить конфигурацию и обнаружение плагина/источника без записи; доступен --json. |
| `plex update` | Загрузить выбранную версию и открыть установку. |
| `plex uninstall` | Удалить неизменённые управляемые роли, инструкции и dev-ссылки/override; сохранить общие зависимости, исходники и настройки. |

`status` и `uninstall` принимают `--project`, повторный `--client` (или `--host`) и `--scope`. Удаление поддерживает `--dry-run` и `--yes`. `--dev`/`--no-dev` применяются только к установке; состояние dev при проверке и удалении определяется автоматически.

## Все параметры установки

Интерактивная установка предлагает режим один раз для всех выбранных клиентов: по умолчанию выбран сохранённый режим, для новой установки — `balanced`. Поле `interaction` всегда явно записывается в применённый preset, в том числе при обновлении старой конфигурации.

| Параметр | Действие |
|---|---|
| `--project PATH` | Существующий проект; без параметра интерактивная установка спросит путь. |
| `--client codex\|claude\|antigravity` | Выбор клиента; повторите параметр для нескольких клиентов. |
| `--host CLIENT` | Совместимый псевдоним для одного клиента; поддерживает также профили конкретного вендора. |
| `--scope project\|user` | Агенты и блок инструкций на уровне проекта (по умолчанию) или пользователя; обычный плагин в обоих случаях общий для пользователя. |
| `--team pnet\|bmad` | Набор ролей; без параметра сохраняется выбранная команда, для новой установки — pnet. |
| `--model-profile PROFILE` | Общий уровень: inherit, basic, plus, pro, pro-plus; текущий профиль сохраняется. Идентификаторы профилей вендоров описаны в конфигурации. |
| `--interaction interactive\|balanced\|auto` | Режим вопросов при работе агентов; сохранённое значение или balanced по умолчанию. |
| `--max-agents N` | Положительный лимит параллельных поручений; текущий лимит сохраняется. |
| `--instructions / --no-instructions` | Управлять только блоком Plex в инструкциях (по умолчанию) или пропустить его. |
| `--dev / --no-dev` | Только Codex, область project: ссылки на скиллы рабочей копии или выход из dev. Нужен управляемый блок инструкций; без параметра dev-режим сохраняется. |
| `--install-bmad` | Разрешить установку выбранных официальных пользовательских скиллов BMad и недостающего проектного runtime; файлы этих скиллов могут заменяться. |
| `--init-bmad` | Инициализировать недостающий runtime BMad официальным установленным setup. |
| `--bmad-skill PATH` | Явный путь к установленному официальному скиллу настройки BMad. |
| `--roles-only` | Не устанавливать плагин Plex; явные параметры зависимостей BMad продолжают действовать. |
| `--command / --no-command` | Создать команду ~/.local/bin/plex (по умолчанию) или пропустить; dev-режим её не устанавливает. |
| `--install-command` | Установить только команду для этой рабочей копии; чужая команда не заменяется. Несовместим с --dev. |
| `--dry-run` | Предпросмотр без записи; несовместим с --install-command. |
| `--yes` | Применить без вопросов; укажите клиента и путь проекта (путь можно опустить при --scope user). Инициализация BMad принимает показанные значения по умолчанию. |
| `--json` | Машиночитаемый вывод status или uninstall. |
| `-h / --help` | Показать доступные параметры. |

## Параметры загрузки и обновления

Для тега релиза: `plex update --release TAG`; для `main`: `plex update --development`. GitHub-установщик принимает те же параметры источника и `--checkout PATH` (по умолчанию `~/.local/share/plex-ai`); `--checkout` относится к загрузчику, а не к setup. `--dry-run` загрузчика/update проверяет только выбор исходников. Остальные параметры установки передаются в setup. Пример:

```sh
curl -fsSL https://raw.githubusercontent.com/pnetcloud/plex-ai/main/install.sh | bash -s -- --release v0.5.1
```

Приоритеты настроек и управляемые файлы описаны в [конфигурации](../../../docs/translations/ru/configuration.md).
