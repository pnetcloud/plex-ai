# Plex AI v0.6.1

Mandatory specialist intake before routing or implementation.

- Every new Plex task and unplanned subtask first goes to native `plex-pm`, including apparently small fixes. Root does not decide complexity or readiness itself.
- PM returns a bounded task contract, existing task/spec format and reference, required roles/order, acceptance checks and readiness. Required technical decisions reach architect in BMad or PM in pnet before dev.
- Intake stays short and role-local: no automatic BMad activation, PRD, persona menu or extra tracker. Actual BMad domain assignments retain their workflow contracts; use installed PO/spec operations when the project requires them.
- Missing or rejected required roles block their work. Root cannot take over the blocked design or implementation. Reuse assessments for already covered steps and unchanged continuation.

## Update

```sh
curl -fsSL https://raw.githubusercontent.com/pnetcloud/plex-ai/main/install.sh | bash
```

Refresh setup and open a new client session. Existing role catalogs may remain stale in an already-running session; re-reading a skill alone does not prove the new roles are callable.

Verification: 167 local tests (166 passed, one skipped without Claude CLI). A native Luna / max coordinator called Sol / medium `plex-pm` for both a one-line edit and an API-design task. PM marked the edit ready and required architect decisions for the API; no implementation or BMad workflow was started during intake.
