# Plex v0.4.0 — Preview

Set up a BMad team from the Plex installer, including missing dependencies and project runtime.

- When project runtime is missing, choose official BMad initialization, `pnet`, or cancel.
- If the setup skill is absent, explicitly approve user-wide installation of the
  selected official BMad skills. Existing plugins stay unchanged; selected user
  skill files may be replaced and other projects share them.
- Install only 21 skills: the team's entry/workflow skills, `bmad`, and two module
  records. The verified official revision includes PO, which the plugin marketplace
  currently lacks. Source: `495ef6e0996d07b23359cc4d6c73a1aa2f3ba5ad`;
  installer: `skills@1.7.4`. No full-repository skill installation.
- Use `--install-bmad` to authorize dependency installation and project initialization,
  or `--init-bmad` for existing dependencies. `--yes` accepts displayed module defaults.
  `--bmad-skill PATH` selects an installed hub explicitly; dry runs do not install.
- Runtime is created by official BMad setup after plan confirmation. Plex does not
  copy skills into the project or implement a second BMad runtime.

## Install or update

```sh
curl -fsSL https://raw.githubusercontent.com/pnetcloud/plex-ai/main/install.sh | bash
```

Select `bmad` in your target project and follow the dependency/runtime choices.
Dependency installation requires Node.js/npm; runtime setup requires `uv`.
Installed dependencies and runtime remain if a later step is cancelled or fails.
Reopen the coding client after installation.

## Validation and limits

111 local tests passed. A real isolated Codex installation verified all 21 selected
skills, official runtime creation and seven native roles without model calls.
Claude Code and Antigravity dependency commands are covered by portable tests;
live end-to-end execution for those clients remains unverified. No new model
benchmark was run. Publication requires Linux/macOS CI with Python 3.11/3.14.
BMad remains a pinned preview dependency; workflow availability and live routing
must still be verified in the active host.
