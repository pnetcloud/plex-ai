# Plex AI v0.14.0

PM now selects the minimal suitable BMad route from the complete role-keyed workflow map. The catalog adds direct entries for PM's concise `bmad-spec`, PO's epics-and-stories, sprint-planning and correct-course workflows, and Dev's walkthrough. Existing PO operations remain available.

Direct workflow entry follows the selected installed skill's own activation and return contract without requiring an unrelated persona. Persona/menu entry retains its declared binding and operation. A missing `operation` does not by itself prove that direct entry is supported, and the root coordinator remains the only dispatcher.

Build reuses accepted requirements. When requirements are missing, only the selected specification workflow or a Build route that supports minimal-spec work may fill the gap before code; Plex does not automatically create a PRD, epic, story or duplicate specification. In `interactive`, PM returns meaningful route options and a recommendation through the root; `auto` selects independently; `balanced` keeps its existing policy. Settled choices and the selected workflow's real reviews and checkpoints are preserved.

No assignment schema, saved preset, session-state format, profile, model or pnet behavior changes. Existing `.plex/resolved.json` snapshots do not update automatically; refresh the selected project configuration to receive the new catalog. Catalog entries do not install BMad skills or prove host availability. Resolver, rendered-role, package and documentation checks do not establish that a running chat loaded the update or that a workflow will complete unattended.
