# Plex AI v0.19.0

Plex now requires semantic validation before code implementation against newly authored or materially revised executable BMad requirements. Validation uses the installed generation's supported operation and project adapter and records the exact requirements bundle, relevant scenarios, terminal acceptance, findings and disposition. Build may investigate, diagnose, plan and draft the implementation spec before this gate. If the spec needs validation, only code implementation pauses; the same Dev resumes at a safe boundary after material gaps are resolved. Already accepted work is not restarted retroactively.

- Require independent review of the exact candidate and requirements before implementation is accepted. A completed, evidenced independent Build review counts once; otherwise the candidate goes to the standalone reviewer.
- Reuse validation and review evidence only while their complete inputs remain unchanged. Preserve later explicit human overrides.
- Apply the guidance in both teams and their translated role contracts. Assignment schemas and saved settings do not change.

Run `plex update` while keeping the current team and profile to refresh the roles. Open a new client session to load them. No format migration is required.

Verification: the exact release commit passed the full local test suite, shell syntax checks and documentation/package checks. These checks do not prove live BMad workflow execution or application behavior.
