# Plex AI v0.15.0

Plex now resumes multi-step work from recorded handoffs and gives PM/PO a concise basis for choosing which specialists a task needs. BMad setup checks the pinned skill catalog before changing user-level skill files.

## Coordination

- Record each handed-off result in coordinator state and advance the parent's `next_action`. A blocked later step does not reopen completed work; repeat PM intake only when evidence or a user decision materially changes the assignment.
- Classify by scope and unresolved decision, not labels such as bug or feature: contained, ready changes go to Dev; product/UX gaps go to PM/PO and UX as needed; new or changed capabilities that cross subsystem/service/data-store boundaries, alter shared interfaces/data ownership/invariants, or lack consistent architecture go to BMad Architect (pnet PM owns the technical plan); unknown causes go to diagnosis.
- Stop diagnosis when the evidenced cause supports a safe repair. Production identity and prior-effect checks gate ACK, replay and mutation; they do not block an isolated fail-closed code fix. If a test runner fails before tests start, make one targeted environment correction or report that check blocked.

## BMad setup

- Check the pinned official source catalog before installing skills. Stop before writing if a required skill is unavailable.
- Install only missing skills, preserve valid existing files, and make partial installs safe to retry. An incomplete existing skill path is left unchanged for inspection.
- Keep workflow entries aligned with skills present in the pinned source.

Refresh project configuration and open a new client session to load updated role instructions. Existing project snapshots and running sessions do not update automatically. If the pinned catalog cannot be verified, skill installation stops before user-level files change.
