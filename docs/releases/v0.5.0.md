# Plex v0.5.0 — Preview

Update existing installations without repeating setup, or test a working checkout with Codex.

- Existing teams offer **Update only** or **Reconfigure**. Refresh retains the team,
  profile, interaction, concurrency, overrides and each client's instruction-block
  choice. Explicit CLI settings still apply; multi-client setup reuses the action.
- Interactive setup includes **interactive / balanced / auto** selection. Every
  applied preset records `interaction`; older presets receive the missing default.
- Codex project `--dev` links both complete Plex skills to this checkout and disables
  the shared Plex plugin only in that trusted project. Managed instructions require
  the project Plex skills; references, checker, coordinator and team resources resolve
  to the same source. BMad remains a separate dependency.
- `--no-dev` and uninstall remove only owned dev links and the owned plugin override.
  Status reports the configured development source. Skill edits follow live links;
  role/profile/catalog changes still require setup refresh and a new client session.
- New instruction markers are `plex:managed:start/end`. Unchanged receipt-owned
  blocks with old markers migrate during refresh, preserving surrounding text.
  Existing vendor profile IDs remain supported during refresh; conflicting files
  and unknown configuration/receipt fields stop changes rather than reset settings.
- Installation and all CLI options now have a dedicated guide in `readme/`, with
  English, Russian, German and Chinese versions linked from root READMEs.

## Install or update

```sh
curl -fsSL https://raw.githubusercontent.com/pnetcloud/plex-ai/main/install.sh | bash
```

For a development checkout, run its installer directly:

```sh
./setup.sh --dev --client codex --project /path/to/test-project
```

Choose project scope. Keep the source checkout available and reopen the client.
Dev mode currently supports Codex only; it does not disable cloud-managed plugins
or other standalone same-name skills. Project configuration requires Codex trust.

## Validation and limits

127 local tests passed, including isolated native Codex checks that verified the
project plugin was disabled, another project remained enabled, and leaving dev
restored plugin discovery. Tests cover update-only settings preservation, older
presets/markers, multi-client instruction choices, conflicts and rollback.
Publication requires Linux/macOS CI with Python 3.11/3.14. Native checks skip when
the client CLI is absent. No model calls or new quality/cost benchmarks were run.
Plugin-manager changes are separate from role-file rollback. This remains a preview.
