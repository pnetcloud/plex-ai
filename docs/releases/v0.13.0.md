# Plex AI v0.13.0

Coordinators can retain the current goal, user decisions and unfinished work in a bounded session checkpoint. New unrelated requests enter a queue; PM intake is required before routing or executing them. The default is at most two active independent outcomes in total, including the primary outcome, separate from agent concurrency.

The shared state template and read-only validator impose an 8,192-byte UTF-8 limit plus field and item limits. Before saving an oversized checkpoint, the coordinator must compact it and retain essential decisions and unfinished commitments through retrievable references. Workers receive their own scoped assignment rather than the global queue. These are coordination instructions and structural checks, not automatic scheduling or proof of semantic preservation.

Both teams also include a native DevOps specialist for assigned CI/CD, release and deployment work. PM intake and project procedures still apply; release and deployment authority remain separate. BMad DevOps does not require a BMad persona.

BMad OpenAI recipes now use medium reasoning for Pro architecture/review, Pro+ architecture/UX/review and Ultra UX. Pro+ and Ultra coordinator recommendations are gpt-6-luna/xhigh and gpt-6.1-sol/medium. Provider recipes are independent; matching tier names do not require identical settings for every role.

Update Plex and refresh project configuration. Preserve project model overrides, review the effective profile settings when upgrading from older releases, and reload the instructions in continuing chats. New role availability may require a fresh client session. Checkpoint files are local working state; installation does not migrate task history or populate a queue automatically.

Package and boundary checks do not establish improved live efficiency, routing or deployment health. Publication and each project update require their own verification.
