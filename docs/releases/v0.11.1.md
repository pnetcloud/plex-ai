# Plex AI v0.11.1

Codex setup now configures native child-thread capacity when no explicit limit is present.

This release includes the native capacity changes prepared for v0.11.0. That tag did not produce a published release because CI caught two outdated dev-mode test expectations. The tests now cover managed capacity and retained table headers with isolated configuration inputs.

- Manage `agents.max_concurrent_threads_per_session` from Plex `max_agents` through the existing configuration transaction, backup and uninstall lifecycle.
- Preserve explicit canonical, legacy and observed inherited limits, including lower limits. Conflicting or invalid values stop changes; uncertain profile or inherited-layer applicability suppresses automatic capacity writes.
- Distinguish unfinished Plex assignments from open native child threads, which exclude the primary thread. Report saved configuration separately from session activation.

Update Plex and refresh the project during an appropriate pause in active work. Existing explicit limits remain user-owned. An unchanged Plex-owned value follows future refreshes unless profile or inherited-layer applicability is uncertain, in which case its block and ownership record remain unchanged. Manual edits are preserved as conflicts requiring review. The installer does not restart Codex. A fresh session is needed to load saved settings; file checks do not prove runtime adoption.

Configuration and lifecycle checks do not establish live model behavior or improved throughput. Client-version compatibility and current-session activation require separate runtime evidence.
