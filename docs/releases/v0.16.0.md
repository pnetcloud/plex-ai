# Plex AI v0.16.0

Plex gives Dev/DevOps ownership of routine execution inside accepted assignments and makes coordinator memory readable in Markdown. Setup migrates existing checkpoints automatically when configuration is applied.

## Coordination

- Escalate material changes to scope, acceptance, shared invariants or authority. Routine technical steps stay with the assigned executor without another PM round.
- Continue independent authorized implementation while measurements, review or delivery are pending. Keep the next action tied to the user's outcome.
- A failed checkpoint candidate blocks that save, not already accepted task work. Preserve the last valid state and repair the checkpoint without reopening intake.
- Pass relevant instruction updates to reused executors; refreshed files alone do not replace a running agent's initial instructions.

## Memory and migration

- New checkpoints use validated Markdown. Capacity is 32 KiB of UTF-8, with up to 16 current decisions and room for exact executor handles. This storage guard does not limit model context or task execution.
- Setup converts valid canonical JSON checkpoints in the selected installation root, verifies the Markdown, backs up originals and removes old files from the working directory. No separate confirmation is needed.
- Migration uses the existing backup/rollback transaction, preserves concurrent changes and keeps Markdown private. Runtime memory does not become installer-owned configuration.
- Conflicting or invalid checkpoints remain intact with warnings. `plex status` reports the observed memory format. Old-path checks can resolve the same session's migrated Markdown and return `canonical_path`.

Run `plex update` and apply the configuration. Source download alone does not migrate projects. Open a new client session to load refreshed role instructions; active sessions may retain earlier instructions.

Verification: 236 tests, shell checks and clean Docker installation checks for Codex, Claude and Antigravity in project and user scopes. Migration checks cover preserved data, repeat updates, legacy paths, conflicts, concurrent writes and rollback. These checks do not establish improved live model behavior.
