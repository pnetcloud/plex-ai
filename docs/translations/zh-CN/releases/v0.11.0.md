# Plex AI v0.11.0

如果未设置明确的限制，Codex 安装流程现在会配置原生子线程数量。

- 根据 Plex 的 `max_agents` 管理 `agents.max_concurrent_threads_per_session`，复用现有的配置事务、备份和卸载流程。
- 保留明确设置的规范参数、旧参数及已发现的继承限制，包括较低的限制。无效或相互冲突的值会阻止修改；无法确定配置档或继承层是否适用时，不自动写入容量设置。
- 区分未完成的 Plex 任务与开放的原生子线程；主线程不计入子线程数量。分别报告已保存的配置与会话是否已采用该配置。

请在适当的工作间歇更新 Plex 并刷新项目配置。明确设置的限制仍由用户管理。未被手动修改的 Plex 托管值会随后续刷新更新。如果无法确定配置档或继承层是否适用，则保留原有配置块与归属记录，不作修改。手动修改会保留，并作为冲突供检查。安装程序不会重启 Codex。需要新会话来加载已保存的设置；文件检查不能证明运行时已采用设置。

配置与生命周期检查不能证明实际模型行为或吞吐量提升。客户端版本兼容性及当前会话的设置采用情况需要单独的运行时证据。
