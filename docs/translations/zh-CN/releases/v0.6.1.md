# Plex AI v0.6.1

路由和实现前必须先由专家评估。

- 每个新 Plex 任务及计划外子任务都先交给原生 `plex-pm`，包括看起来很小的修改。Root 不自行判断复杂度或就绪状态。
- PM 返回任务契约、已有任务格式与引用、角色及顺序、验证标准和就绪状态。开发前，必要的技术决策交给 BMad architect 或 pnet PM。
- 评估简短且在角色内部完成：不自动激活 BMad、PRD、persona 菜单或新 tracker。真正的 BMad 任务仍遵守工作流；按项目支持情况使用 PO/spec 操作。
- 所需角色缺失或被拒绝时，仅阻塞该任务；root 不接管其设计或实现。已覆盖步骤和未改变的继续工作复用已有评估。

## Update

```sh
curl -fsSL https://raw.githubusercontent.com/pnetcloud/plex-ai/main/install.sh | bash
```

更新配置并打开新客户端会话。已有会话可能保留旧角色目录；重新读取技能并不能证明新角色可调用。

验证：167 项本地测试，166 项通过，一项因缺少 Claude CLI 跳过。原生 Luna / max 协调者分别将单行修改和 API 设计任务交给 Sol / medium 的 `plex-pm`。PM 判定前者可实施，后者需要架构决策；评估期间没有启动实现或 BMad 工作流。
