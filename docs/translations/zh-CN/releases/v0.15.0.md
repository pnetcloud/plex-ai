# Plex AI v0.15.0

Plex 现在会根据已记录的交接继续多步骤任务。PM/PO 可以依据简明规则选择所需专家。BMad Setup 会先检查固定版本的技能目录，再修改用户级技能文件。

## 协调

- 每个已交付结果都会记录在协调器状态中，并更新上级任务的 `next_action`。后续步骤受阻时不会重新打开已完成工作；只有证据或用户决策实质改变任务时才重新进行 PM 评估。
- 根据变更范围和未决事项分类，而不是根据“缺陷”或“功能”等标签：边界清晰且可直接实施的变更交给 Dev；产品/UX 问题交给 PM/PO，并在需要定义用户路径、交互或设计时使用 UX；跨子系统、服务或数据存储的新/变更能力，涉及共享接口、数据归属或不变量的变更，以及缺失或矛盾的架构，应交给 BMad Architect。pnet 团队由 PM 负责技术规划；原因未知时进入诊断流程。
- 一旦有证据支持安全修复，就结束诊断。生产环境中的身份与既有影响检查是 ACK、重放和数据变更的前提，但不应阻止可安全挂起未知情况的隔离代码修复。如果测试运行器在测试开始前失败，应进行一次针对性的环境修正，或将该检查标记为受阻。

## BMad 安装

- 安装技能前先检查固定官方源的目录。若缺少必需技能，Setup 会在写入前停止。
- 只安装缺失的技能，保留有效的现有文件；部分安装可以安全重试。现有的不完整技能路径保持原样，以供检查。
- Workflow 目录仅包含固定源中实际存在的技能。

请刷新项目配置并开启新的客户端会话，以加载更新后的角色指令。现有项目快照和运行中的会话不会自动更新。若无法验证固定技能目录，安装会在更改用户级文件前停止。
