# Plex v0.5.0 — Preview

无需重复配置即可更新现有安装，也可通过 Codex 测试工作副本。

- 现有团队提供 **Update only** 或 **Reconfigure**。更新保留团队、模型配置、
  交互模式、并发数、覆盖设置和每个客户端的指令区块选择。显式 CLI 参数仍有效；
  多个客户端复用所选操作。
- 交互安装提供 **interactive / balanced / auto**。每个应用的 preset 都保存
  `interaction`，旧配置会补充缺失默认值。
- Codex 项目级 `--dev` 将两个完整的 Plex 技能目录链接到工作副本，
  仅在此受信任项目中禁用共享插件。托管指令要求使用项目技能；引用、检查脚本、
  协调器和团队资源来自同一源。BMad 仍为独立依赖。
- `--no-dev` 和卸载仅清理 Plex 拥有的开发链接及插件覆盖区块。
  Status 显示开发源。技能修改通过实时链接可见；角色、配置档或目录修改仍需刷新安装并新建会话。
- 新标记为 `plex:managed:start/end`。更新时迁移未修改的旧托管区块，保留周围文本。
  刷新时保留现有厂商专用模型配置标识。文件冲突或配置、安装记录中的未知字段会阻止更改，
  不会重置设置。
- 安装及全部 CLI 参数现位于 `readme/`，提供英、俄、德、中四种版本，并从根 README 链接。

## 安装或更新

```sh
curl -fsSL https://raw.githubusercontent.com/pnetcloud/plex-ai/main/install.sh | bash
```

开发副本请直接运行其安装器：

```sh
./setup.sh --dev --client codex --project /path/to/test-project
```

选择项目范围，保留工作副本并重新打开客户端。开发模式目前仅支持 Codex，
不会禁用云端插件或其他同名技能。Codex 必须信任项目才能加载其配置。

## 验证与限制

127 项本地测试通过，包括隔离的原生 Codex 检查：测试项目中禁用插件，
另一项目中保持启用，退出开发模式后恢复。覆盖更新保留、旧配置及标记、
多客户端指令选择、冲突与回滚。发布要求通过 Linux/macOS 和 Python 3.11/3.14 CI；
缺少客户端 CLI 时跳过原生检查。未调用模型，未进行新的质量或成本基准测试。
插件管理器更改与角色文件回滚分离。此版本仍为预览版。
