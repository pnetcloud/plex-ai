# Plex AI v0.19.0

现在，基于新编写或实质修改的 BMad 可执行需求实现代码前，必须先进行语义验证。验证使用已安装版本支持的操作和项目适配器，并记录准确的需求输入集、相关场景、最终验收条件、发现及处理结果。Build 可以先调查、诊断、规划并起草实现规格。如果规格需要验证，只暂停代码实现；实质缺口解决后，同一 Dev 在安全边界继续。已接受的工作不会因此追溯重启。

- 接受实现前，必须独立审查准确的候选改动和需求。已完成且有证据的 Build 内部独立审查只计一次；否则将候选交给独立 reviewer。
- 只有完整输入未变化时，才可复用验证和审查证据。之后明确的人工决定仍然有效。
- 已更新两个团队的指令及各语言角色契约。任务 schema 和已保存设置保持不变。

运行 `plex update` 并保留当前团队和配置档位，以刷新角色。打开新的客户端会话以加载更新后的角色。无需格式迁移。

验证：在准确的发布提交上，完整本地测试套件、shell 语法及文档/打包检查均已通过。这些检查不证明实时 BMad 工作流执行或应用行为。
