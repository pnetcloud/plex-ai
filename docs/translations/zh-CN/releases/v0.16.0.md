# Plex AI v0.16.0

Plex 将已接受任务范围内的常规技术步骤交给 Dev/DevOps，并以 Markdown 展示协调器状态。应用配置时，Setup 会自动迁移现有状态文件。

## 协调

- 范围、验收、共享不变量或权限发生重要变化时，交回相应决策负责人。常规技术步骤由已分配的执行者完成，无需再次经过 PM。
- 等待测量、审查或交付时，继续独立且已授权的实现工作。下一步始终围绕用户要求的结果。
- 无效的状态候选只阻止该次保存，不阻止已接受的任务。保留最后一个有效状态，并修复候选文件，无需重新评估任务。
- 将适用的指令变更传给复用的执行者；更新文件不会自动替换运行中代理最初加载的指令。

## 状态与迁移

- 新状态使用经过校验的 Markdown。容量为 32 KiB UTF-8，最多保存 16 项当前决策，并容纳准确的执行者标识。此存储限制不限制模型上下文或任务执行。
- Setup 在所选安装范围内转换有效的规范 JSON 状态，校验 Markdown、备份原文件，并移除工作目录中的旧文件，无需额外确认。
- 迁移使用现有备份与回滚事务，保留并发修改并保护 Markdown 的私密性。运行状态不会成为安装器管理的配置。
- 有冲突或无效的状态保持原样并报告警告。`plex status` 显示实际格式；旧路径检查可读取同一会话迁移后的 Markdown，并返回 `canonical_path`。

运行 `plex update` 并应用配置。仅下载源代码不会迁移项目。开启新的客户端会话以加载更新后的角色指令；活动会话可能仍保留旧指令。

验证包括 236 项测试、Shell 检查，以及 Codex、Claude、Antigravity 在项目级和用户级的干净 Docker 安装检查。迁移检查覆盖数据保留、重复更新、旧路径、冲突、并发写入及回滚。这些检查不能证明真实模型行为已改善。
