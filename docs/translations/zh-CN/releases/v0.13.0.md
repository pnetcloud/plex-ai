# Plex AI v0.13.0

协调器可以在有大小限制的会话状态文件中保存当前目标、用户决策和尚未完成的工作。新的独立请求先进入队列，选择执行路径或开始执行前必须进行 PM 初步评估。默认最多同时推进两个独立方向，主要目标包含在这两个方向之内；此限制与代理并发数量分开计算。

共享模板和只读校验器将状态限制为 8192 个 UTF-8 字节，并限制字段长度和条目数量。保存超限状态前，协调器必须压缩内容，通过可检索的引用保留重要决策和未完成的承诺。执行代理只接收自己的任务，无需读取全局队列。这些规则和结构校验不提供自动调度，也不能证明语义完整性。

两个团队还新增了原生 DevOps 专家，用于明确分配的 CI/CD、发布和部署任务。仍须遵守 PM 初步评估和项目流程；发布权限与部署权限分别授权。BMad DevOps 无需 BMad 角色激活。

BMad 的 OpenAI 配方现为 Pro 的架构/评审、Pro+ 的架构/UX/评审以及 Ultra 的 UX 使用 medium 推理强度。Pro+ 和 Ultra 的协调器建议分别为 gpt-6-luna/xhigh 和 gpt-6.1-sol/medium。各提供商配方独立定义；相同档位名称不要求每个角色的设置完全一致。

更新 Plex 并刷新项目配置。保留模型覆盖设置，从旧版本升级时检查最终生效的模型配置，并让继续运行的聊天重新读取指令。新角色可能需要新的客户端会话才能使用。状态文件属于本地工作数据；安装过程不会迁移任务历史或自动填充队列。

软件包与边界测试不能证明实际团队效率、实际路由或部署健康状态有所改善。发布和每个项目的更新都需要分别验证。
