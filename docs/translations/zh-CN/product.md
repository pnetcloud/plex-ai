# 关于 Plex

[English](../../product.md) · [Русский](../ru/product.md) · [Deutsch](../de/product.md) · [简体中文](product.md)

**组建团队，协调工作。**

Plex 是面向软件开发的智能体 harness，支持 OpenAI Codex、Anthropic Claude Code
和 Google Antigravity。它在现有客户端中组合可复用技能、原生智能体角色、团队配置和模型配置档。
名称源自 *multiplex*：让多方贡献汇入同一个协调过程。

## 目标

团队需要明确的任务、相关上下文、唯一的文件写入责任人，以及能够验证结果的检查。
Plex 使这些职责跨项目保持可检查、可重复。编排选择角色并安排依赖；协调使各方工作保持一致；
harness 提供可复用的配置。

## 原则

- 委派有明确边界、结果和责任人的工作。
- 将角色与模型选择分开，保留根会话设置。
- 只使用任务需要的能力，不强制每个角色都参与。
- 遵守项目指令、客户端权限和真实的用户决策。
- 验证行为和实际路由后，再提出质量、速度或节省方面的结论。

## 两种操作

1. **配置：**通过源码安装器或 `plex-setup` 安装共享技能，并在项目或用户范围应用团队和配置档。
2. **协调：**需要团队合作时，显式调用 `plex`。安装和任务复杂度本身不会自动启用协调。

`pnet` 可独立工作。`bmad` 激活已有的 BMad 角色与工作流；规划、实现、审查及适用检查点由 BMad 管理。

## 主对话与团队

**根协调者就是当前主对话。** 在其中调用 `plex`，提供任务、约束和预期结果。
协调者选择有用的委派任务、传递上下文、安排依赖并整合已验证的结果。
子智能体执行有明确边界的工作；PM 负责规划任务，并不取代根协调者。
可用角色是一套工具，不是每个任务都必须经过的步骤。

请在客户端选择主对话模型。安装器会显示所选配置档的协调模型建议，但不会设置或切换该模型。
不同配置档的建议模型和推理强度可能不同；`inherit` 保留会话选择，不给出具体建议。
根对话负责协调时，仍可由轻量模型完成实现工作。

模型配置档**只配置子智能体**。安装计划将主对话建议与各角色的有效模型设置分开显示，
后者包含本地覆盖。设置为 `inherit` 的角色遵循客户端或会话默认设置，
因此主对话的模型选择也可能影响这些子智能体。建议只是起点，并非经实测确定的质量或成本最优配置。

参见[角色职责](role-contracts.md)和[安装说明](installation.md)。

## 范围

Plex 没有独立守护进程或界面，仅在明确授权后安装 所选 BMad 技能依赖，不替换其工作流、不部署应用，也不保证工作流内部子智能体的模型路由。
通过 Antigravity 使用 Gemini 模型不代表支持 Gemini CLI。

参见[配置](configuration.md)、[兼容性](host-compatibility.md)和[实测结果](testing.md)。
