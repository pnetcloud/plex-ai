## 范围与方法

证据时间范围：2026 年 10 月 16–18 日。这些开发验证运行采用同一个 Focus Session 任务：
响应式本地 HTML/CSS/JS 表单，包含校验、时长摘要、键盘操作和减少动态效果，无后端或持久化。
独立 Chromium 验收包含 12 项检查。耗时包括智能体执行、自测和审查，不包括安装和独立验收，
并四舍五入到秒。

表格仅列出保留的已完成运行，并非所有尝试或成功率。额度中断和工作流中止不算完成。
原始会话和审计证据另行保存；此处仅提供经过核对的汇总。

## 测试如何进行

1. 将冻结的 Focus Session 任务复制到全新临时项目，应用团队和配置档，保存源码与配置快照，不复用先前应用实现。
2. 使用记录的根任务启动原生客户端，运行限制为 900 秒。让实现、必需审查和修正完成，不向执行者提供独立验收脚本。
3. 审核实际子模型、上下文传递、工作流分支与完成情况。CLI 退出码为零不足以证明成功。
4. 通过本地 loopback 服务器执行独立浏览器验收，检查桌面与 360px 手机截图，保留命令和结果。
5. 汇总每个线程自身的用量、历史成本估算、事件和源码哈希，区分应用缺陷、协调失败与测试环境修正。

最新 Codex 测试使用 Codex CLI 0.163.0、Python 3.14.3，以及通过 Xvfb 运行的带界面缓存 Chromium。BMad 插件清单显示 6.13.0-next，但最新实际 build 来自无精确版本清单的全局技能，通过源码哈希确认来源。配置档名称指保存的设置，不代表当前模型目录。

任务要求纯 HTML/CSS/JavaScript：trim 后至少两个字符的姓名、有效邮箱、25/50 分钟时长、字段错误、本地确认及保留输入值。没有后端、存储、依赖或外部请求。所有完成运行均使用以下十二类验收：

| 编号 | 独立验收 |
|---|---|
| 1 | 结构和可访问字段标签 |
| 2 | 空表单校验 |
| 3 | 错误与相应字段关联 |
| 4 | 无效姓名与邮箱 |
| 5 | trim 后姓名校验 |
| 6 | 有效确认、保留值且无持久化 |
| 7 | 实时更新时长摘要 |
| 8 | 真实键盘提交与焦点 |
| 9 | 360px 布局无横向溢出 |
| 10 | 遵守减少动态效果偏好 |
| 11 | 无 JavaScript 错误 |
| 12 | 无外部请求 |

| 配置 | 未缓存输入 | 缓存输入 | 输出 | 其中推理 |

| pnet Basic | 106,523 | 1,618,560 | 25,550 | 7,770 |

Token 是所有模型响应及子会话的累计用量，不是单次上下文大小。每个会话的自身用量只计算一次，
不重复计算继承历史。总量 = 未缓存输入 + 缓存输入 + 输出。推理 Token 已包含在输出中。
最新 Codex 用量已与 Tokscale 交叉核对。

USD 估算按实际模型求和：`(非缓存输入 × 输入费率 + 缓存输入 × 缓存费率 + 输出 × 输出费率) / 1,000,000`。历史费率见下文，推理输出不重复计算。

## 描述性统计

最新每种配置均为 **n = 1 次完成运行**。下表比较这些单次观测，`/` 后是基准。负值表示更少时间、成本或 token，并非平均因果效应估计。

| 比较 | 时间变化 | 成本变化 | Token 变化 |
|---|---|---|---|
| BMad Basic / pnet Basic | +13.8% | +2.1% | +14.7% |
| BMad Plus / pnet Plus | +141.5% | +11.6% | +383.5% |
| BMad Basic / pnet Plus | -18.0% | -77.5% | +35.5% |

| 配置 | 输入缓存占比 | 含根线程的线程数 |
|---|---|---|
| pnet Basic | 93.8% | 4 |
| pnet Plus | 85.0% | 4 |
| BMad Basic | 94.6% | 3 |
| BMad Plus | 96.6% | 4 |

在这一配对中，BMad Basic 比 pnet Plus 的**估算成本低 77.5%**、**时间少 18.0%**，且项目所有者认为结果质量相当，但总 token 多 35.5%。不同模型费率和缓存复用使 token 数不能替代成本。

BMad Plus 耗时为 pnet Plus 的 2.41 倍，成本为 1.12 倍。原因未被隔离：推理、调查、审查、上下文和缓存均不同。缓存占比 = 缓存输入 / 全部输入；线程数包含根线程，不表示峰值并发。

单次配置无法估计配置内方差、置信区间、显著性或普遍成功概率。合并修订版会混合不同处理条件。十二项检查是同一任务的断言，不是十二个独立任务试验。

## 质量评估

项目负责人的定性评估是：**BMad Basic 的感知结果质量与 pnet Plus 相当**，
即引入方法流程可能带来约一个配置等级的提升。这是专家观察，也是有待进一步测试的假设。
BMad 产物包含最小规格说明和审查分类记录；相同的 12/12 验收分数既不能衡量这种质量差异，
也不能证明其原因。

应将 UX、完整性、可维护性、残留缺陷和验证质量与时间及费用分开评估，最好对多个任务和重复运行进行盲评。

没有独立盲评小组、对这些结果实际应用的评分量表或数字化主观评分。因此不事后编造 1–10 分或质量百分比。

| 质量维度 | 证据支持的内容 |
|---|---|
| 必需行为 | 所有完成运行均为 12/12；验收不对这些结果排序 |
| 整体感知质量 | 所有者评价：BMad Basic 与 pnet Plus 相当；其他配置和客户端没有已确立的主观排名 |
| 流程完整度 | BMad 保留最小规格、路线和审查分诊；pnet 完成 PM → dev → reviewer → 修正 |
| 审查价值 | pnet 发现输入边界情况和手机截断；BMad 在修正前记录输入、确认文案和 live region 问题 |
| 可维护性与剩余缺陷 | 没有盲评比较分数或穷尽缺陷搜索；未测试屏幕阅读器实际输出 |

审查发现是中间观测，不是最终验收失败。数量不代表质量，BMad 审查配方本身要求最低发现数量。

## 协调观察

- 两次最新 pnet 根线程均启动 PM、dev 和 reviewer，再让同一开发者进行一次修正。所有子线程继承完整对话。这两次运行未观察到丢失任务或阻塞性用户问题。
- Basic 重复探索配置和浏览器环境；Plus 保留可复用检查及精确命令。环境重试和重复验证增加工作量，不等于应用缺陷。
- BMad Basic 使用 root → dev → 工作流 reviewer。最新 BMad Plus 增加有边界的架构扫描，完成一次适用的 Blind Hunter 审查，没有错误批准暂停。
- 实际模型：pnet Basic 全部 Luna/high；pnet Plus 根 Luna/high、PM Sol/low、dev Luna/max、reviewer Sol/medium。BMad Basic 全部 Luna/high；BMad Plus 根 Luna/high、dev/reviewer Luna/max、architect Sol/medium。Sol 指 `gpt-6.1-sol`，Luna 指 `gpt-6-luna`。
- BMad 内部 reviewer 未自动使用独立 reviewer 配置。原生日志中的直接交接正文已加密；可读回复、目标、元数据及行为支持所述顺序。

优化候选包括精简任务上下文、复用有效验证命令、按实际分支检查关卡，以及显式映射工作流内部模型。这些是基于观察到的阻力提出的建议，并非已实施修改带来的实测节省。

## 限制与实践结论

- 这些单次运行的提示、路径、缓存和工具不同，不能据此对配置或厂商进行统计排名。
- 费用使用历史 API 等价费率估算，不是当前价格、订阅额度或供应商账单。每百万输入/缓存/输出 Token 的 USD 费率：Luna 0.10/0.01/0.50；Sol 2/0.10/10；Astra 10/1/50；Sonnet 3/0.30/15；Flash 0.15/0.015/0.60。
- 渲染成功不能证明运行时模型选择。BMad 内部审查并不自动使用独立 reviewer 角色的模型配置，必须记录实际子模型。
- 最新 build 使用全局安装的 BMad 技能；仅查看插件清单无法确定实际工作流。纯插件环境尚未单独验证。
- Codex 使用隔离配置和针对测试 VM 的完全访问调整，普通沙箱及屏幕阅读器播报尚未验证。
- 在最近四次已完成运行中，pnet Basic 最快且最便宜；这不能证明其普遍更优，也不能保证更高配置等级必然改善结果。

## 下一轮受控比较

在多种任务上比较 Basic + BMad 与 Plus + pnet，每个冻结配置/任务至少运行三次全新试验并交替顺序。对需求、UX、可维护性、剩余缺陷和验证质量分别盲评；冻结任务、验收、技能、配置档哈希、上下文策略和费率快照。

保留每次尝试和干预，报告完成率、成功运行时间及成本的中位数与范围、所有尝试成本除以完成任务数。具体效应量可能需要更多重复；三次只是起始协议，不保证统计功效。在此之前，“提升一个配置档位”仍是可检验的假设。
