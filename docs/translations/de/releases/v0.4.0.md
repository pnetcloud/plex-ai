# Plex v0.4.0 — Preview

BMad-Team aus dem Plex-Installer einrichten, einschließlich Abhängigkeiten und Projekt-Runtime.

- Ohne Runtime stehen offizielle Initialisierung, `pnet` oder Abbruch zur Wahl.
- Fehlt der Setup-Skill, eine separate Benutzerinstallation ausgewählter offizieller
  Skills bestätigen. Vorhandene Plugins bleiben unverändert; ausgewählte Benutzerdateien
  können ersetzt werden und werden von anderen Projekten mitgenutzt.
- Nur 21 Skills werden installiert: Team-Einstieg-/Workflow-Skills, `bmad` und zwei
  Moduldatensätze. Die geprüfte offizielle Revision enthält PO, das im Plugin-Marketplace
  noch fehlt: `495ef6e0996d07b23359cc4d6c73a1aa2f3ba5ad`; Installer: `skills@1.7.4`.
  Nicht alle Skills des Repositorys werden installiert.
- `--install-bmad` erlaubt Installation und Initialisierung; `--init-bmad` nutzt
  vorhandene Abhängigkeiten. `--yes` akzeptiert angezeigte Modulstandards.
  `--bmad-skill PATH` wählt den Hub. Dry-run installiert nichts.
- Das offizielle BMad-Setup erstellt Runtime nach Planbestätigung. Plex kopiert
  keine Skills ins Projekt und implementiert keine zweite BMad-Runtime.

## Installation und Update

```sh
curl -fsSL https://raw.githubusercontent.com/pnetcloud/plex-ai/main/install.sh | bash
```

Im Zielprojekt `bmad` wählen und Installation/Initialisierung folgen. Node.js/npm
werden für Abhängigkeiten, `uv` für Runtime benötigt. Abhängigkeiten und Runtime
bleiben bei späterem Abbruch/Fehler erhalten. Den Client anschließend neu öffnen.

## Prüfung und Grenzen

111 lokale Tests bestanden. Ein realer isolierter Codex-Lauf prüfte alle 21 Skills,
offizielle Runtime und sieben native Rollen ohne Modellaufrufe. Claude-Code-/Antigravity-
Befehle sind durch portable Tests abgedeckt; ihre vollständige Live-Ausführung bleibt
ungeprüft. Keine neuen Modell-Benchmarks. Veröffentlichung erfordert Linux/macOS-CI
mit Python 3.11/3.14. BMad bleibt eine festgelegte Preview-Abhängigkeit; Workflow-
Verfügbarkeit und Live-Modellrouting müssen im aktiven Client geprüft werden.
