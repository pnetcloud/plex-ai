# Plex AI v0.7.0

PM/PO-geführte Aufträge und begrenzte Ausführung bis zum nachgewiesenen Ergebnis.

- PM/PO wählt normale Ausführung, Planung zuerst oder zielorientierte Arbeit mit einem bis fünf beobachtbaren Abnahmekriterien. Root koordiniert Aufträge und integriert Nachweise.
- Ein kompakter JSON-Vertrag und ein schreibfreier Validator prüfen Rolle, Eingaben, Grenzen, Bereitschaft und Ausführungsangaben anhand des geprüften Team-Snapshots. Bestehende Issues/Specs/Stories bleiben maßgeblich.
- Native Plan/Goal-Modi sind optional. Sonst normal planen oder begrenzt nach Kriterien arbeiten. Native Goal fordert standardmäßig 50.000 Tokens ohne automatische Erneuerung an; fehlende Zählung wird ausdrücklich gemeldet.
- Installiertes `bmad-build-auto` steht für eine unbeaufsichtigte Iteration bereit. Renderer, Pflicht-Subagenten, Review und Endprotokoll bleiben erhalten; akzeptierte Spezifikationen benötigen keinen zweiten Planungsprozess.
- Agenten wiederverwenden und nur geänderte Informationen übergeben. Unerledigte Aufträge getrennt von nativen Thread-Slots zählen; exakte Artefaktpfade/Revisionen erhalten, keine ähnlich benannten Dateien ersetzen.

## Aktualisierung

```sh
curl -fsSL https://raw.githubusercontent.com/pnetcloud/plex-ai/main/install.sh | bash
```

Setup aktualisieren und eine neue Client-Sitzung öffnen, damit Rollen und Workflow-Katalog geladen werden. Teamrollen, Modellprofile und Setup-Schnittstellen bleiben unverändert.

Prüfung: 174 lokale Tests (173 bestanden, einer ohne Claude CLI übersprungen); sechs Offline-Docker-Installationszyklen für alle Clients und beide Geltungsbereiche. Native pnet-Ausführung und eine installierte BMad-Build-Auto-Iteration einschließlich vier Workflow-Reviewern abgeschlossen. Live-Smokes liefen ohne Sandbox, da `bwrap` auf dem Testhost nicht initialisiert werden konnte; native Goal-Aktivierung, Budgetdurchsetzung und automatische Fortsetzung wurden nicht geprüft.
