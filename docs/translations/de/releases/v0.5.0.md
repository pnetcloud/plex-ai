# Plex v0.5.0 — Preview

Vorhandene Installationen ohne wiederholte Einrichtung aktualisieren oder einen Checkout mit Codex testen.

- Vorhandene Teams bieten **Update only** oder **Reconfigure**. Update behält Team,
  Profil, Interaktion, Parallelität, Overrides und den Anweisungsblock pro Client.
  Explizite CLI-Optionen gelten weiter; mehrere Clients verwenden dieselbe Aktion.
- Interaktives Setup bietet **interactive / balanced / auto**. Jeder angewendete
  Preset speichert `interaction`; ältere Presets erhalten den fehlenden Standardwert.
- Codex-Projektmodus `--dev` verlinkt beide vollständigen Plex-Skill-Ordner zum
  Checkout und deaktiviert das gemeinsame Plugin nur in diesem vertrauenswürdigen
  Projekt. Der Anweisungsblock verlangt projektlokale Plex-Skills; Referenzen,
  Prüfskript, Koordinator und Teamressourcen stammen aus derselben Quelle.
  BMad bleibt eine getrennte Abhängigkeit.
- `--no-dev` und Deinstallation entfernen nur eigene Links und Plugin-Overrides.
  Status zeigt die Entwicklungsquelle. Skills folgen Live-Links; Rollen-, Profil-
  und Katalogänderungen benötigen Setup-Aktualisierung und eine neue Sitzung.
- Neue Marker: `plex:managed:start/end`. Unveränderte eigene alte Blöcke werden beim
  Update migriert; umgebender Text bleibt erhalten. Vorhandene Anbieter-Profil-IDs
  bleiben bei Updates gültig. Konflikte oder unbekannte Konfigurations-/Belegfelder
  stoppen Änderungen statt Einstellungen zurückzusetzen.
- Installation und alle CLI-Optionen stehen in `readme/`, auf Englisch, Russisch,
  Deutsch und Chinesisch mit Links aus den Haupt-READMEs.

## Installation oder Update

```sh
curl -fsSL https://raw.githubusercontent.com/pnetcloud/plex-ai/main/install.sh | bash
```

Für einen Entwicklungscheckout dessen Installer direkt starten:

```sh
./setup.sh --dev --client codex --project /path/to/test-project
```

Projektbereich wählen, Checkout verfügbar halten und den Client neu öffnen.
Dev unterstützt derzeit nur Codex; Cloud-Plugins oder andere gleichnamige Skills
werden nicht deaktiviert. Codex muss dem Projekt für die lokale Konfiguration vertrauen.

## Prüfung und Grenzen

127 lokale Tests bestanden, einschließlich isolierter nativer Codex-Prüfungen:
Plugin im Testprojekt deaktiviert, im anderen Projekt aktiv und nach Dev-Ende
wieder aktiv. Abgedeckt sind Update-Erhalt, alte Presets/Marker, Anweisungen mehrerer
Clients, Konflikte und Rollback. Veröffentlichung erfordert Linux/macOS-CI mit
Python 3.11/3.14; native Prüfungen werden ohne passende CLI übersprungen.
Keine Modellaufrufe oder neuen Qualitäts-/Kostenbenchmarks. Plugin-Änderungen sind
vom Rollen-Rollback getrennt. Dies bleibt eine Vorschauversion.
