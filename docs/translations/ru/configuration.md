## Установка и обновление

Для первой установки используйте [быстрый старт](../../../README.ru.md#быстрый-старт).
Скрипт хранит общую копию в `~/.local/share/plex-ai` и запускает настройку из текущей
папки проекта. Сохраняйте эту копию: установленные плагины ссылаются на неё.
Та же команда обновляет её и снова открывает настройку:

```sh
curl -fsSL https://raw.githubusercontent.com/pnetcloud/plex-ai/main/install.sh | bash
```

Обновление использует fast-forward Git pull; конфликтующие локальные изменения
останавливают обновление. Проверьте план, примените новые роли/профили и перезагрузите
клиент. `~/.local/bin/plex` открывает настройку без скачивания обновлений;
запрос Plex внутри клиента запускает координацию.

Из checkout запустите `./setup.sh`. Пробел отмечает клиентов, Enter продолжает.
Выберите команду, область установки и общий профиль; проверьте план каждого клиента.
По умолчанию выбрана область проекта. Нужен установленный CLI соответствующего клиента.

```sh
./setup.sh --project /path/to/project --client codex --client antigravity --team pnet --model-profile plus --yes
```

Полная установка добавляет общий плагин Plex и настраивает нативные роли/инструкции.
Скилы не дублируются в проектах. Пока локальный marketplace ссылается на исходники
или экспорт, сохраняйте их. Для BMad нужны установленный runtime проекта и подходящие скилы.

Повторный setup обновляет определения или переключает команду/профиль, сохраняя
переопределения. Изменения попадут в установленные роли после обновления; для загрузки
новых скилов/ролей начните свежую сессию клиента. Общий профиль проекта обновляет
уже настроенных клиентов; клиент без receipt не устанавливается автоматически.

| Опция | Действие |
|---|---|
| `--dry-run` | Предпросмотр без записи |
| `--roles-only` | Роли/состояние без установки плагина |
| `--no-instructions` | Пропустить управляемый блок инструкций |
| `--no-command` | Не создавать ярлык `~/.local/bin/plex` |
| `--install-command` | Установить только ярлык checkout |
| `--max-agents N` | Общий лимит поручений |

Изменения менеджера плагинов и завершённые установки клиентов не откатываются при сбое следующего клиента.

## Команды и профили

| Команда | Роли | Процесс |
|---|---|---|
| `pnet` | pm, explorer, researcher, dev, reviewer, qa | Самостоятельная координация |
| `bmad` | analyst, pm, po, ux, architect, dev, reviewer | Существующие скилы BMad |

Профили: `inherit`, `basic`, `plus`, `pro`, `pro-plus`. Общие уровни объединяют
OpenAI для Codex, Anthropic для Claude Code и Google для Antigravity внутри команды.
`inherit` оставляет модель и effort клиенту. Профиль задаёт настройки, а не измеренный уровень качества.

Редактируемый файл в корне выбранной области — `.plex/preset.toml`:

```toml
team = "pnet"
model_profile = "plus"
max_agents = 3

[codex.dev]
reasoning = "max"
```

Приоритет каждого поля: **профиль → роль профиля → клиент → роль клиента**.
Таблицы `[codex]`, `[claude]`, `[antigravity]` задают общие значения; суффикс роли — исключения.
Поля: `model`, `reasoning`. Для наследования модели в Codex не задавайте `model`.
Переключение команды сохраняет неактивные переопределения отсутствующих ролей.

Определения: `teams/<team>/team.toml`, `agents/<host>/`, `profiles/*.toml`.
Файл поставщика содержит один клиент и независимые уровни; цепочек включения нет.
Точные ID моделей и effort находятся в этих файлах, без дублирования таблицами в документации.

ID вроде `openai-plus`, `google-anthropic-plus` доступны через одноклиентский
`--host` и resolver. Многоклиентский `--client` использует общие уровни.
Одноклиентское меню custom меняет переопределения ролей именованного профиля;
`custom` не сохраняется как профиль. Доступность моделей зависит от клиента и провайдера.

## Область проекта и пользователя

| Клиент | Роли проекта | Корень пользователя / каталог ролей |
|---|---|---|
| Codex | `.codex/agents/` | `$CODEX_HOME` или `~/.codex` / `agents/` |
| Claude Code | `.claude/agents/` | `$CLAUDE_CONFIG_DIR` или `~/.claude` / `agents/` |
| Antigravity | `.agents/agents/` | `~/.gemini` / `config/agents/` |

Каждая область содержит своё состояние `.plex`. `check --host <host> --scope auto`
сначала выбирает проект, иначе пользователя. Устаревший или конфликтующий проект
не заменяется пользовательской командой автоматически. Смена области не удаляет и
не переносит другую. Пользовательские роли BMad требуют runtime в каждом рабочем проекте.

## Управляемые инструкции и состояние

Plex владеет только блоком `<!-- plex:start -->` … `<!-- plex:end -->`.
Личные инструкции оставляйте снаружи. Изменённые, удалённые, повторные или некорректные
маркеры вызывают конфликт вместо перезаписи пользовательских изменений.

Выбирается существующий непустой файл либо создаётся стандартный: Codex —
`AGENTS.override.md`, затем `AGENTS.md`, затем fallback проекта; Claude — `CLAUDE.md`,
затем проектный `.claude/CLAUDE.md`; Antigravity — `GEMINI.md`, затем проектный `AGENTS.md`.
Fallback Codex не используется в пользовательской области. Выбор не меняет настройки
fallback клиента и не заставляет его читать дополнительный файл.

| Файл | Назначение |
|---|---|
| `.plex/preset.toml` | Редактируемая команда, профиль и переопределения |
| `.plex/resolved.json` | Сгенерированный снимок настроек |
| `.plex/applied.json` | Receipt клиента и хеши управляемых файлов |
| `.plex/backups/` | Заменённые файлы и выведенные из команды роли |

Не редактируйте сгенерированные роли и receipts вручную. Чужие файлы, изменённые
управляемые данные, симлинки и параллельные apply блокируют небезопасное обновление.
Разберите конфликт до повторного setup и сохраняйте резервные копии.

## Проверка без применения

Из checkout Plex, Python 3.11+:

```sh
python3 skills/plex-setup/scripts/resolve_config.py list
python3 skills/plex-setup/scripts/resolve_config.py resolve /path/to/project/.plex/preset.toml
python3 skills/plex-setup/scripts/resolve_config.py render /path/to/project/.plex/preset.toml --host codex
python3 skills/plex-setup/scripts/resolve_config.py check /path/to/project --host codex --scope auto
```

`apply` записывает нативную конфигурацию; для инструкций прямому вызову resolver нужен
явный `--instructions`. Установщик объединяет предпросмотр, плагин и интеграцию инструкций.

Необязательная политика ревью BMad описана [здесь](../../../teams/bmad/review-policy.md).
Обычная установка её не включает.
