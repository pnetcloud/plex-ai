# Plex AI v0.6.1

Обязательная оценка специалиста перед выбором маршрута и реализацией.

- Каждая новая задача Plex и незапланированная подзадача сначала передаётся нативному `plex-pm`, включая внешне простые правки. Root сам не оценивает сложность и готовность.
- PM возвращает контракт задачи, принятый формат и ссылку, нужные роли и порядок, критерии и готовность. Нужные технические решения до dev получает архитектор BMad или PM в pnet.
- Оценка короткая и выполняется внутри роли: без автоматической активации BMad, PRD, меню персоны или нового tracker. Настоящие BMad-поручения сохраняют свои workflow; PO/spec используются там, где поддерживаются процессом проекта.
- Недоступная или отклонённая обязательная роль блокирует своё поручение; root не заменяет её проектирование или реализацию. Для уже охваченных шагов и неизменного продолжения оценка переиспользуется.

## Update

```sh
curl -fsSL https://raw.githubusercontent.com/pnetcloud/plex-ai/main/install.sh | bash
```

Обновите настройку и откройте новую сессию клиента. Уже запущенная сессия может сохранить старый каталог ролей; перечитывание скилла не доказывает доступность новых ролей.

Проверка: 167 локальных тестов — 166 прошли, один пропущен без Claude CLI. Нативный координатор Luna / max вызвал `plex-pm` на Sol / medium и для правки одной строки, и для API-задачи. PM признал правку готовой, а для API потребовал решения архитектора; реализация и BMad workflow при оценке не запускались.
