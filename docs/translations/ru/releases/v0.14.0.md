# Plex AI v0.14.0

Теперь PM выбирает минимально достаточный маршрут BMad по полной карте workflows с ключами ролей. В каталог добавлены прямые входы для краткой спецификации `bmad-spec` у PM, workflows планирования эпиков и историй, спринта и корректировки плана у PO, а также walkthrough у Dev. Существующие операции PO сохранены.

При прямом входе выполняются собственные правила активации и возврата выбранного установленного skill; запуск посторонней персоны не требуется. Для входа через персону или меню сохраняются объявленная привязка и операция. Отсутствие `operation` само по себе не доказывает поддержку прямого входа. Единственным диспетчером остаётся корневой координатор.

Build использует уже принятые требования. Если их не хватает, пробел до начала кода может закрыть только выбранный workflow спецификации или маршрут Build, чей установленный контракт поддерживает минимальную спецификацию. Plex автоматически не создаёт PRD, epic, story или дублирующую спецификацию. В `interactive` PM возвращает существенные варианты и рекомендацию через корневой чат; в `auto` выбирает самостоятельно; правила `balanced` не меняются. Выбранный маршрут, реальные проверки и контрольные точки workflow сохраняются.

Схема заданий, сохранённые пресеты, формат состояния сессии, профили, модели и поведение pnet не меняются. Существующий `.plex/resolved.json` автоматически не обновляется; чтобы получить новый каталог, обновите конфигурацию выбранного проекта. Наличие записи в каталоге не устанавливает BMad skills и не доказывает их доступность на хосте. Проверки resolver, сгенерированных ролей, пакета и документации не доказывают, что открытый чат загрузил обновление или что workflow завершится без участия человека.
