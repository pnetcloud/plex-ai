# Plex v0.4.0 — Preview

Настройка команды BMad из установщика Plex: зависимости и runtime проекта.

- Если runtime отсутствует, выберите официальную инициализацию, `pnet` или отмену.
- Если нет setup-скилла, отдельно подтвердите установку выбранных официальных skills
  для пользователя. Существующие плагины остаются нетронутыми; выбранные пользовательские
  skill-файлы могут быть заменены и используются другими проектами.
- Устанавливается только 21 skill: входные/workflow-skills команды, `bmad` и две
  записи модулей. Проверенная официальная ревизия содержит PO, которого пока нет в
  plugin marketplace: `495ef6e0996d07b23359cc4d6c73a1aa2f3ba5ad`. Установщик —
  `skills@1.7.4`. Все skills репозитория не устанавливаются.
- `--install-bmad` разрешает установку зависимостей и инициализацию;
  `--init-bmad` использует уже установленные зависимости. `--yes` принимает показанные
  значения модулей по умолчанию. `--bmad-skill PATH` задаёт hub явно. Dry-run не устанавливает.
- Runtime создаётся официальным setup после подтверждения плана. Plex не копирует
  skills в проект и не создаёт собственную реализацию runtime BMad.

## Установка и обновление

```sh
curl -fsSL https://raw.githubusercontent.com/pnetcloud/plex-ai/main/install.sh | bash
```

Выберите `bmad` в целевом проекте и следуйте вариантам установки/инициализации.
Для зависимостей нужны Node.js/npm, для runtime — `uv`. Установленные зависимости
и runtime сохраняются при отмене или ошибке следующего шага. Затем перезапустите клиент.

## Проверки и ограничения

Локально прошли 111 тестов. В реальном изолированном профиле Codex проверены все 21 skill,
официальная инициализация и семь нативных ролей без вызовов моделей. Команды для Claude Code
и Antigravity покрыты переносимыми тестами; живой полный сценарий этих клиентов не проверялся.
Новых модельных бенчмарков не проводилось. Публикация требует CI Linux/macOS на Python 3.11/3.14.
BMad остаётся зафиксированной preview-зависимостью; доступность workflows и маршрутизацию
моделей нужно проверять в активном клиенте.
