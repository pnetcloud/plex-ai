## Установка

Запускайте из папки проекта. Нужны Git, curl, CLI клиента и uv или Python 3.11+.

**Обычная**

```sh
curl -fsSL https://raw.githubusercontent.com/pnetcloud/plex-ai/main/install.sh | bash
```

**Dev-режим · Codex**

```sh
curl -fsSL https://raw.githubusercontent.com/pnetcloud/plex-ai/main/install.sh | bash -s -- --dev --client codex
```

Выберите клиента, область, команду и профиль, затем подтвердите план. Рекомендуется область **Project**. После установки откройте новую сессию клиента.

В финальном вопросе **Apply this plan?** при установке и обновлении выбрано **Yes**. Выберите **No**, чтобы отменить. Архивирование других агентов и удаление по-прежнему требуют отдельного подтверждения.

Профиль настраивает субагентов. Модель root coordinator выбирайте в основном чате;
план показывает рекомендацию. Подробнее: [основной чат и команда](product.md#основной-чат-и-команда).

Установщик регистрирует общий плагин Plex и применяет выбранную команду. Плагин даёт скиллы; настройка команды добавляет нативные роли и управляемый блок инструкций. В dev-режиме используются локальные ссылки на скиллы.

[Примеры запросов в чате](README.md#примеры-в-чате).

## Короткие имена скиллов · Codex

Обычная установка добавляет `$plex` и `$plex-setup` через ссылки на общую рабочую копию Plex; плагин остаётся включённым. Для проекта ссылки находятся в `.agents/skills/`, для пользователя — в `$CODEX_HOME/skills/` (по умолчанию `~/.codex/skills/`). Содержимое скиллов не копируется. Сохраняйте исходную рабочую копию.

Для существующей установки один раз обновите настройку и откройте новую сессию Codex. Чужие скиллы сохраняются и отмечаются как конфликт. `--roles-only` сохраняет уже настроенные ссылки, но не добавляет их при новой установке. Полные имена с префиксом плагина также доступны.

## Другие агенты Codex

Поручения Plex используют только точные имена `plex-<role>` из проверенной активной команды. Другие установленные и встроенные агенты в неё не входят; исполнители внутри workflow следуют контракту этого workflow.

Установщик показывает другие `.toml`-агенты выбранной области и предлагает **Сохранить** (по умолчанию) или **Переместить в backup**. Они доступны клиенту и могут влиять на выбор исполнителя. Подходящие файлы перемещаются в `.plex/backups/<timestamp>/codex/other-agents/`; при необходимости восстановите файл вручную из этой папки. Другие области, символические ссылки и файлы с явной регистрацией в `config.toml` сохраняются. Изменённые управляемые роли остаются конфликтами.

Для нативного выбора ролей Codex нужны доверенная конфигурация проекта и новая сессия. Установщик управляет нужными параметрами выбора роли с резервированием и проверкой владения; конфликтующие личные значения сохраняются. См. [конфигурацию](configuration.md).

Если нет явного нативного лимита, установщик сохраняет лимит дочерних потоков Codex из `max_agents`. Preview, apply и status отдельно показывают незавершённые поручения Plex и максимальное число открытых дочерних потоков (основной поток исключён). Активация в сессии остаётся неизвестной, пока её не проверят в Codex. Установщик не перезапускает Codex.

Если неизвестна применимость профиля или родительской конфигурации, существующий
неизменённый блок Plex и квитанция остаются прежними, даже если меняется
`max_agents`. Plex снимает свой ключ при известном применимом наследуемом лимите
или при наличии такого же локального старого псевдонима.

Для очистки без вопросов укажите `--archive-other-agents --client codex`; один `--yes` сохраняет других агентов. `--dry-run` никогда не перемещает файлы.

## Основные команды

Если команды `plex` нет — например, после первой dev-установки — используйте `~/.local/share/plex-ai/setup.sh` вместо `plex` в командах ниже.

| Задача | Команда |
|---|---|
| Настроить или обновить конфигурацию проекта | `plex` |
| Проверить конфигурацию | `plex status` |
| Загрузить новый релиз и открыть установщик | `plex update` |
| Посмотреть план установки без записи | `plex --dry-run --client codex --project .` |
| Посмотреть план удаления | `plex uninstall --dry-run` |
| Удалить команду проекта | `plex uninstall` |
| Получить статус в JSON | `plex status --json` |
| Получить план удаления в JSON | `plex uninstall --dry-run --json` |

Если команда уже установлена:

| Параметр | Назначение |
|---|---|
| **Update only** | Сохранить настройки и обновить управляемые файлы. |
| **Reconfigure** | Открыть меню с сохранёнными значениями. |

Явные параметры CLI продолжают действовать. `plex` использует текущую рабочую копию; `plex update` загружает новый опубликованный релиз, включая preview.

## Dev-режим

- Только Codex и область **project**. Обе папки скиллов Plex подключаются ссылками на исходники; сохраняйте эту рабочую копию.
- В проекте отключается общий плагин, а управляемый блок инструкций выбирает локальные скиллы Plex. Codex должен доверять проекту. Облачные плагины и другие одноимённые скиллы не отключаются.
- Изменения скиллов доступны через ссылки. После изменения ролей, профилей и каталога workflow обновите установку и откройте новую сессию. Режим сохраняется до `--no-dev`.

| Задача | Команда |
|---|---|
| Подключить рабочую копию | `./setup.sh --dev --client codex --project /path/to/project` |
| Вернуться к общему плагину | `./setup.sh --no-dev --client codex --project /path/to/project` |

## BMad

Нужны Node.js/npm и uv. Выберите команду `bmad` в меню или выполните:

| Задача | Команда |
|---|---|
| Установить выбранные официальные скиллы и runtime проекта | `plex --team bmad --client codex --install-bmad` |
| Инициализировать проект из уже установленных скиллов | `plex --team bmad --client codex --init-bmad` |

Skills общие для пользователя. Сначала setup проверяет закреплённый исходник, устанавливает только отсутствующие выбранные skills и сохраняет существующие корректные файлы. Неполный путь skill не изменяется и останавливает установку до проверки. Runtime принадлежит проекту. Установленные зависимости/runtime остаются после отмены или последующей ошибки. Для запуска без вопросов добавьте `--project . --yes`: принимаются показанные значения BMad по умолчанию.

Setup также автоматически переводит корректную память координатора из JSON в
Markdown в выбранной установке, используя штатные резервные копии и rollback.
Отдельного подтверждения нет. `plex status` показывает формат памяти; конфликтные
или некорректные файлы сохраняются с предупреждением.

## Удаление

**Команда проекта** · запустите из папки проекта:

```sh
plex uninstall --dry-run
plex uninstall
```

Удаляются неизменённые управляемые роли, принадлежащий Plex блок инструкций и его ссылки на скиллы и dev-override. Инструкции за пределами блока сохраняются. Изменённые управляемые файлы останавливают удаление для проверки.

**Команда уровня пользователя** · выберите клиента, для которого ставили глобальные роли:

```sh
plex uninstall --scope user --client codex
```

**Общий плагин** · удаляйте, когда остальные проекты больше в нём не нуждаются. Выполните команду своего клиента:

| Клиент | Команда |
|---|---|
| Codex | `codex plugin remove pnet-plex@pnet-plex` |
| Claude Code | `claude plugin uninstall pnet-plex@pnet-plex --scope user` |
| Antigravity | `agy plugin uninstall pnet-plex` |

В Codex плагин также можно удалить через браузер `/plugins`. См. [руководство OpenAI](https://learn.chatgpt.com/docs/plugins#remove-a-plugin) и [справочник Claude Code](https://code.claude.com/docs/en/plugins/cli-reference#plugin-uninstall).

При удалении команды остаются настройки и backups в `.plex`, зависимости/runtime BMad, необязательная команда запуска и исходная рабочая копия. Удаление плагина — отдельная операция клиента; команды других проектов оно не удаляет. Сохраняйте общую рабочую копию, пока её использует какой-либо проект или dev-ссылка.

## Справочник параметров

Пропущенные настройки сохраняют свои значения. `interaction` явно записывается в каждый применённый preset. Профили, переопределения и пути описаны в [конфигурации](configuration.md).

### Клиенты и область

| Параметр | Назначение |
|---|---|
| `--project PATH` | Существующая папка проекта. |
| `--client CLIENT` | codex, claude или antigravity; можно повторить для нескольких клиентов. |
| `--host CLIENT` | Совместимый псевдоним одного клиента; допускает профили вендоров. |
| `--scope project / user` | Область ролей/инструкций; по умолчанию project. Обычные плагины общие для пользователя. |
| `--instructions / --no-instructions` | Управлять блоком Plex в инструкциях или пропустить его. |

### Команда и модели

| Параметр | Назначение |
|---|---|
| `--team pnet / bmad` | Набор ролей; для новой установки — pnet. |
| `--model-profile PROFILE` | inherit, basic, plus, pro, pro-plus, ultra или ultra-plus. |
| `--interaction MODE` | interactive, balanced (по умолчанию) или auto. |
| `--max-agents N` | Положительный лимит незавершённых поручений Plex; нативная ёмкость потоков Codex показывается отдельно. |

### Выполнение и вывод

| Параметр | Назначение |
|---|---|
| `--dev / --no-dev` | Подключить локальные скиллы или выйти из dev; только Codex/project. |
| `--archive-other-agents` | Codex: явно разрешить перенос других подходящих агентов выбранной области в backup. |
| `--roles-only` | Не устанавливать плагин Plex; явные флаги BMad действуют. |
| `--command / --no-command` | Создать ~/.local/bin/plex (по умолчанию) или пропустить; dev не создаёт команду. |
| `--install-command` | Установить только команду; чужую не заменяет, несовместим с --dev. |
| `--dry-run` | Предпросмотр без записи; несовместим с --install-command. |
| `--yes` | Применить без вопросов; нужны клиент и путь проекта (путь необязателен при --scope user). |
| `--json` | JSON для status или uninstall, включая план удаления. |
| `-h / --help` | Показать сгруппированную справку и примеры. |

### BMad

| Параметр | Назначение |
|---|---|
| `--install-bmad` | Разрешить установку выбранных пользовательских скиллов и недостающего runtime. |
| `--init-bmad` | Инициализировать runtime установленным официальным setup. |
| `--bmad-skill PATH` | Явный путь к установленному setup-скиллу BMad. |

### Источник — update / GitHub-установщик

| Параметр | Назначение |
|---|---|
| `--release TAG` | Использовать тег релиза, например v0.5.11. |
| `--development` | Использовать main; не включает --dev. |
| `--checkout PATH` | Только GitHub-установщик; по умолчанию ~/.local/share/plex-ai. |

GitHub-установщик хранит общую рабочую копию в `~/.local/share/plex-ai`; не удаляйте её. `--dry-run` загрузчика/update проверяет только выбор исходников; остальные параметры передаются в setup.

## Сохранность файлов и решение проблем

- Удаляются также неизменённые параметры маршрутизации Codex, принадлежащие Plex по receipt; совпадающие настройки, существовавшие до установки, остаются личными.
- Удаление по умолчанию работает на уровне проекта. `--client codex` ограничивает клиента, `--scope user` выбирает пользовательские роли, `--yes` подтверждает удаление без вопросов.
- Удаляются только неизменённые управляемые роли, блоки инструкций и ссылки на скиллы и dev-override. Общие плагины, исходники, настройки и backups остаются; изменённые управляемые файлы и неизвестные форматы останавливают операцию.
- Обновление исходников отказывается менять грязную, чужую или подключённую симлинком копию. Изменения менеджера плагинов и завершённые установки клиентов отделены от отката файлов ролей.
- `status` сначала проверяет проект, иначе — пользовательскую область. Он проверяет конфигурацию и обнаружение плагина, а не фактический выбор моделей.

| Если… | Что использовать |
|---|---|
| plex отсутствует в PATH | ~/.local/bin/plex или ./setup.sh из рабочей копии. |
| Команда принадлежит другой копии | Напечатанный путь к setup.sh; чужая команда сохраняется. |
| Конфликт скилла или управляемого файла | Проверьте указанный файл: установщик его не перезаписывает. |
| Существующий override плагина блокирует --dev | Вручную задайте enabled = false; существующий override сохраняется после выхода. |

## Вывод

Цвет включается только в терминале. `NO_COLOR=1` или `TERM=dumb` включает простой вывод и меню с номерами; перенаправленный вывод обычный. С `--json` в stdout нет оформления и сообщений о ходе работы.
