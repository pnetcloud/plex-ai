## Структура исходников

| Путь | Назначение |
|---|---|
| `install.sh` | Скачивание/обновление из GitHub |
| `setup.sh`, `setup.py` | Установщик и необязательный ярлык `plex` |
| `skills/plex/` | Явная координация и preflight |
| `skills/plex-setup/` | Setup, resolver и шаблон управляемых инструкций |
| `teams/<team>/` | Команда, корневой контракт, роли и профили |
| `plugins/<host>/` | Нативные манифесты |
| `.build/plugins/<host>/` | Сгенерированные самостоятельные пакеты |
| `tests/` | Конфигурация, упаковка и изолированная установка |
| `docs/` | Английский текст и переводы |
| `_bmad/custom/` | Настройка BMad для разработки |

Перед изменением поведения читайте продукт, архитектуру и конфигурацию; перед
изменением промптов/команды — контракты ролей. Сохраняйте чужие изменения.
Не делайте commit и публикацию без запроса.

## Проверки

Набор тестов поддерживается в рабочей копии разработки и не входит в публичную
предварительную версию. Команда ниже требует наличия `tests/`.

Из корня репозитория:

```sh
uv run --with pyyaml --with questionary==2.1.1 python -m unittest discover -s tests -v
```

Тесты проверяют разрешение настроек, области, блоки, переопределения, конфликты,
откат, рендеринг, упаковку и временную установку при наличии CLI. Вызовов моделей нет.
Конфигурационные проверки не доказывают маршрутизацию, качество, задержку и экономию:
используйте [протокол](../../../EVALUATION.md). Сводка измерений — в [тестировании](testing.md),
сырые данные хранятся отдельно.

## BMad для разработки репозитория

Установите нужные официальные скилы/плагины BMad через менеджер клиента, затем выполните
setup установленного Toolbox `bmad` из репозитория. Он создаст `_bmad/`; общая настройка
указывает на `docs/` и `_bmad-output/`. Не копируйте runtime из vendor и не создавайте
второй способ bootstrap.

При наличии runtime проверьте конфигурацию:

```sh
uv run _bmad/scripts/resolve_config.py --project-root .
```

Если глобальные и плагинные скилы сосуществуют, установите фактическую активную
идентичность. Setup проекта не должен удалять или обновлять глобальные скилы.

## Упаковка и документация

Публичные папки и маски типов файлов в `.gitignore` определяют экспорт. Runtime разработки, машинные пути,
реестры и сырые эксперименты не входят в клиентские пакеты. Менеджеры устанавливают
`.build/plugins/<host>`, а не только манифест. Сохраняйте зарегистрированные локальные
источники. Установщик использует существующий resolver и путь применения.

Основной текст — `docs/`; `translations/ru`, `translations/de`, `translations/zh-CN`
повторяют имена и каталог шаблонов. Обновляйте версии и навигацию вместе. Числа тестов
должны совпадать; качественные оценки отмечайте явно. Устаревшие исследования и
миграционные заметки убирайте из действующих руководств.
