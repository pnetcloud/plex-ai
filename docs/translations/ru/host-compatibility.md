# Совместимость клиентов

[English](../../host-compatibility.md) · [Русский](host-compatibility.md) · [Deutsch](../de/host-compatibility.md) · [简体中文](../zh-CN/host-compatibility.md)

Клиент исполняет агентов, поставщик предоставляет модели. Профиль поставщика не добавляет адаптер клиента.

| Клиент | Интеграция Plex | Проверки |
|---|---|---|
| OpenAI Codex | TOML-роли, плагин, области и инструкции | Изолированная установка/конфигурация и живые задачи |
| Anthropic Claude Code | Markdown-роли и путь установки плагина | CLI 2.1.310: валидация манифеста, изолированная установка плагина и настройка обеих команд; прогоны с моделями не подтверждены |
| Google Antigravity | Markdown-роли и пакет плагина | Установка/конфигурация и отдельные живые испытания моделей |

Покрытие ограничено проверенными версиями и настройками: см. [тестирование](testing.md).
Gemini CLI — отдельный неподдерживаемый клиент. Новые адаптеры вне текущего охвата.

## Модели и разрешения

Codex получает `model`, `model_reasoning_effort`; Claude Code и Antigravity — `model`,
`effort`. Доступность зависит от реального клиента и модели. Рендеринг Antigravity
принимает `inherit`, `flash_lite`, `flash`, `pro`. Явный ID семейства в профиле не
доказывает поддержку исполнения: неподдерживаемая маршрутизация вызывает сообщение,
а не скрытую подмену. `inherit` наследует модель родителя и не выбирает Sonnet/Opus
независимо для каждого дочернего агента.

Нативные разрешения и лимиты имеют силу. Название роли, профиль и успешный рендеринг
не доказывают изоляцию инструментов, параллелизм или выбор модели. Plex не включает
другого клиента и не ослабляет глобальные разрешения ради работы адаптера.

Субагенты Codex наследуют sandbox, согласования и MCP основного чата. Plex не
записывает `sandbox_mode` и `approval_policy` в TOML ролей. Настраивайте права
в основном чате; инструкция «только чтение» не создаёт отдельный sandbox.
См. [справочник субагентов Codex](https://learn.chatgpt.com/docs/agent-configuration/subagents).

## Делегирование в Claude Code

Plex выбирает нативную роль через `Agent.subagent_type`. Метку задачи передаём в
`description` и тексте задания: параметр `name` может запустить teammate Agent Teams.
Для `delegation = false` генерируется `disallowedTools: Agent`. Роли BMad сохраняют
вложенное делегирование в пределах разрешений и глубины установленного клиента.
См. [справочник субагентов Claude](https://code.claude.com/docs/en/sub-agents).

Поддержка моделей и effort зависит от клиента и модели. Настройки сессии/провайдера,
включая `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` и `CLAUDE_CODE_EFFORT_LEVEL`, могут иметь
приоритет над ролью. Проверяйте фактическое исполнение перед выводами о маршрутизации.

Установщик Claude управляет узкими allow-правилами в `.claude/settings.local.json` (для области user — `settings.json` в конфигурационной папке Claude). Полная установка получает реальный путь к кэшу из нативного inventory и явно обновляет существующий плагин. Roles-only refresh сохраняет записанный путь; автономный resolver использует свой пакет или исходники. Личные правила сохраняются. Изменение управляемого правила считается конфликтом; удаляются только правила Plex, с backup и rollback. Для BMad добавляется чтение папок установленных скиллов, без общего разрешения запускать runtime. Установка BMad для Claude использует `--copy`, сохраняя отдельные копии Codex.

Проверенный абсолютный путь плагина передаётся в Markdown Inputs. Проверка файлов не доказывает права активной сессии или маршрутизацию моделей; после обновления плагина перезапустите Claude. Проверки охватывают установку CLI 2.1.310, обновление кэша и конфигурацию, а не все сочетания моделей и профилей.
